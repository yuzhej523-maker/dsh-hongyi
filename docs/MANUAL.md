# 鸿驿 · 数据手册

> 本手册面向「要在这台电脑上把鸿驿跑起来」的人。照着做即可，不需要读源码。
>
> 版本：v0.1.0（协议 v1）　最后更新：2026-11-10

---

## 0. 一分钟看懂鸿驿

鸿驿让**你的手机在任何网络下**都能看到这台电脑上的 DSH 状态、任务进度，并给 DSH 下发指令、互传文件。

它**不自建任何服务器**。中转用的是一只能收发邮件的邮箱：

```
手机 APK  ⇄  QQ 邮箱（草稿箱，静默）  ⇄  DSH 电脑端插件
```

- 手机在 4G/5G、公司 WiFi、国外酒店网络，都能用——因为中间是邮箱。
- 邮件**写进草稿箱**而不是收件箱，所以不进收件箱、不弹新邮件提醒，只有鸿驿自己读得到。
- 所有消息都带 HMAC-SHA256 签名，篡改会被拒收；文件分片收发，收齐后按 sha256 校验。
- **除「自由文本指令」外，全程不调用任何模型**——遥测、文件传输、结构化指令都是本地代码直接读写邮箱。

前提只有一个：**电脑要开着，DSH 要运行**。电脑关机期间消息留在信箱里（TTL 1 小时），回来开机会补收。

## 1. 准备

### 1.1 需要什么

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 | 也支持 macOS / Linux，路径写法不同 |
| Node.js | ≥ 20 | `node -v` 检查 |
| DSH | 桌面版 | 已安装并能打开 |
| 邮箱 | 支持 IMAP/SMTP | **推荐 QQ 邮箱**（本手册以此为例） |
| 手机 | Android 7.0+ | 装鸿驿 APK |

### 1.2 不需要什么

- ❌ 不需要公网 IP、不需要端口映射（家庭宽带大多是运营商级 NAT，本来也做不了）
- ❌ 不需要自建服务器、不需要域名
- ❌ 不需要在同一 WiFi
- ❌ 不需要安装 WorkBuddy 或腾讯文档客户端

## 2. 获取 QQ 邮箱授权码 ★

这是整件事**唯一容易卡住**的一步，单独讲清楚。

### 2.1 先理解：授权码 ≠ 登录密码

| | 登录密码 | 授权码 |
| --- | --- | --- |
| 用途 | 在网页/客户端登录 QQ 邮箱 | 给**第三方程序**用 IMAP/SMTP 收发邮件 |
| 长度 | 你自己的密码 | 16 位随机字符（如 `abcdwxyzefghijkl`） |
| 泄露后果 | 别人能登你邮箱 | 别人能以你身份收发邮件，但**不能登录网页版** |
| 能否查看 | 随时可改 | **生成时只显示一次**，丢了只能重新生成 |

鸿驿用的是**授权码**。填登录密码会报 `AUTHENTICATE failed` 或「授权码无效」。

### 2.2 分步操作（网页版）

> 手机 QQ 邮箱 App 里也能开，路径是「我的 → 设置 → 账号 → IMAP/SMTP 服务」，但网页版更清楚，**推荐用电脑浏览器**。

1. **用电脑浏览器打开** <https://mail.qq.com>，登录你要用的 QQ 邮箱。

2. 点右上角 **「设置」**（齿轮图标），进入 **「账号」** 页（旧版叫「账户」）。

   > 如果看到的是新版「设置 → 账号与安全」，找 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」** 这一节，不同版本用词略有差异，认准 **IMAP/SMTP** 字样。

3. 找到 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」**，点击 **「开启服务」**。

4. 在弹窗里勾选 **「IMAP/SMTP 服务」**（要发信才能用，别只开 POP3）。

5. 按提示**用绑定手机发送一条短信**到指定号码（内容形如 `配置邮件客户端`），发送后点「我已发送」。

6. 验证通过后，页面会弹出一个 **16 位授权码**，形如：

   ```
   mvdpiztlcreejdag
   ```

   **立刻复制保存。** 关掉弹窗就再也看不到了。

7. 记下你的邮箱地址，例如 `1309427334@qq.com`。

### 2.3 如果第 6 步之后忘了授权码

回到同一个页面，点「生成授权码」可以**重新生成一个**。新授权码生效后，**旧的立即失效**——如果手机和电脑都已配好，重新生成后两边都要改。

### 2.4 常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 找不到「IMAP/SMTP 服务」这一节 | QQ 邮箱版本差异 | 在设置里搜「IMAP」，或换用手机 App 的「设置 → 账号」 |
| 点开启后提示「需要实名认证」 | 账号未实名 | 先在 QQ 安全中心完成实名 |
| 提示「发送短信验证」但收不到 | 绑定手机号已变更 | 先在账号安全里更新绑定手机号 |
| 填了授权码仍报 `AUTHENTICATE failed` | ① 填了登录密码 ② 授权码已过期/被重新生成 ③ 多复制了空格 | 重新生成授权码，复制时注意首尾不要带空格 |
| 报 `LOGIN failed` 且提示「请使用授权码登录」 | 同上 | 同上 |

### 2.5 非 QQ 邮箱

| 服务商 | IMAP | SMTP | 备注 |
| --- | --- | --- | --- |
| 163 | `imap.163.com:993` | `smtp.163.com:465` | 需在设置里开启 IMAP/SMTP 并获取授权码 |
| Gmail | `imap.gmail.com:993` | `smtp.gmail.com:465` | 需开启两步验证后创建「应用专用密码」 |
| Outlook | `outlook.office365.com:993` | `smtp.office365.com:587` | 部分账号需管理员开启 IMAP |

> **静默通道对非 QQ 邮箱的兼容性**：鸿驿默认把邮件写进「草稿箱」以避开新邮件提醒。QQ 邮箱实测支持（APPEND / SEARCH ALL / FETCH / EXPUNGE 全部可用）。**QQ 不允许创建自定义文件夹**（`CREATE` 返回 `NO [CANNOT] Invalid folder name`），所以只能用系统自带的 Drafts。若你的邮箱连草稿箱写入都不支持，在设置里关掉「静默通道」——会退回收件箱模式，代价是会看到邮件提醒。

## 3. 安装鸿驿插件（电脑端）

### 3.1 方式 A：从本地目录安装（开发/自用）

```powershell
# 用 DSH 自带的 CLI，注意 --profile desktop（桌面版用的是 desktop profile）
& "D:\Software\10_AI_Tools\deepseekharness\resources\runtime\cli\bin\dsh.cmd" `
  plugin --profile desktop add "D:\hongyi-build\hongyi"
```

**⚠️ 不要用插件市场面板安装。** 当前 DSH 版本里面板安装会触发宿主内 reload 缺陷（`profile reload requires the root Include entry`），装完即被回滚。用 CLI 装完**手动重启桌面版**才生效。

### 3.2 方式 B：从 tarball 安装

```powershell
npm pack            # 产出 dsh-hongyi-0.1.0.tgz
& "...\dsh.cmd" plugin --profile desktop add ".\dsh-hongyi-0.1.0.tgz"
```

### 3.3 装完检查

重启 DSH 桌面版后：

1. 打开 **设置**，左侧/卡片区应出现 **「鸿驿」**（order 36，在「WorkBuddy 联动」附近）。
2. 在命令行里试：`/hongyi status` → 应返回插件版本与协议版本。
3. 浏览器访问 `http://127.0.0.1:<GUI端口>/hongyi/state` → 应返回含 `"plugin":"dsh-hongyi"` 的 JSON。

> GUI 端口每次重启会变。用 `netstat -ano | findstr LISTENING` 配合进程 PID 找，或者直接看 DSH 启动时打印的地址。

**如果看不到鸿驿卡片**，多半是插件没被组合进去。检查 `%DSH_HOME%\profiles\desktop\package.json`：

- `dependencies` 里有 `"dsh-hongyi"`；
- **`dsh.profile.bundles` 数组里也要有 `"dsh-hongyi"`**（只有 dependencies 不够）。

## 4. 配置鸿驿（电脑端）

打开 设置 → 鸿驿，按顺序填：

### 4.1 云端信箱

| 字段 | 填什么 | 说明 |
| --- | --- | --- |
| 通道 | **邮箱 · 静默通道** | 从下拉里选 `imap` |
| 邮箱地址 | `你的QQ号@qq.com` | |
| 邮箱服务商 | QQ 邮箱 | 决定 IMAP/SMTP 服务器地址 |
| IMAP/SMTP 授权码 | 第 2 步拿到的 16 位码 | 填一次即可，之后显示为掩码 |
| 静默通道 | ✅ 勾选 | 写草稿箱、不弹提醒 |
| 信箱名 | `dsh-hongyi` | 手机端必须填一样的 |

填完点 **「保存」**，再点 **「测试连接」**——应显示「写入并读回成功，签名校验通过（xx ms）」。

### 4.2 设备密钥

同一张卡片往下滚，找到 **「设备密钥」**：

1. 点 **「生成新密钥」**（如果还没生成）。
2. 点 **「显示」** 看明文，点 **「复制」** 复制。

这是一串 32 位字符，例如：

```
d93fb3b47d12d4f644b944d7e1dae176
```

**手机端要填一模一样的一串。** 它用于给每条消息做 HMAC 签名——两端不一致，消息会被对方拒收（日志里会看到 `signature mismatch (bad device secret)`）。

> 也可以直接跑 `/hongyi secret` 在命令行里看到明文。

### 4.3 自检

点 **「自检」**，理想结果是 **9/9 通过**。逐项含义：

| 检查项 | 通过标准 |
| --- | --- |
| Node 版本 | ≥ 20 |
| 工作目录可写 | `$DSH_HOME/hongyi` 能写 |
| 离线队列目录 | 能创建 |
| 信箱驱动 | 显示 `imap` |
| 设备密钥 | 已设置 |
| 信箱可达 | HTTP 200 或草稿箱可读写 |
| 协议版本 | 信箱 v1 vs 插件 v1 |
| 企微 webhook | 未配置也 OK（可选加速项） |
| WorkBuddy 联动 | 占位，不影响 |

## 5. 安装手机 APK

### 5.1 安装

把 `鸿驿.apk` 传到手机（微信/QQ/U 盘/数据线都行），点击安装。首次安装需要允许「安装未知来源应用」。

### 5.2 首次配置

打开 App → **设置** 页，填四项：

| 字段 | 填什么 |
| --- | --- |
| 邮箱服务商 | QQ 邮箱 |
| 邮箱地址 | 与电脑端**完全一致** |
| IMAP/SMTP 授权码 | 与电脑端**完全一致**的 16 位码 |
| 设备密钥 | 与电脑端**完全一致**的 32 位串 |

点 **「保存并连接」** → 顶部出现 **「✔ 已连接」** 即成功。

配置会持久化，下次打开不用重填。

### 5.3 验证联调

1. 手机 **状态** 页应看到 **「电脑在线」** + 邮箱通道 + 「最近遥测」时间（15 秒内会刷新）。
2. 手机 **指令** 页点「查状态」→ 几秒到几十秒后出现绿 ✓ 和回执文本。
3. **传输** 页点「选择文件并发送」→ 电脑端 `%DSH_HOME%\hongyi\inbox\` 出现该文件。

> **延迟说明**：电脑每 15 秒轮询一次，QQ 邮箱索引还有 10~40 秒延迟，所以端到端通常 **15~60 秒**。这不是卡住。

## 6. 目录与数据

所有数据在 `%DSH_HOME%\hongyi\`（默认 `C:\Users\<你>\.dsh\hongyi\`，本机是 `D:\dsh-data\.dsh\hongyi\`）：

| 路径 | 内容 | 能不能删 |
| --- | --- | --- |
| `config.json` | 配置（不含密码） | 删了要重配 |
| `credentials.json` | 授权码 / 设备密钥 | ⚠️ 删了要重配 |
| `journal.ndjson` | 操作日志（指令流水来源） | 可删，会丢历史 |
| `inbound.json` | 幂等账本（记住处理过的消息 id） | 可删，会重放旧消息 |
| `queue/outbound.json` | 待发队列 | 可删 |
| `queue/needs-model.json` | 待云端解析的自由文本指令 | 可删 |
| `inbox/` | 收到的文件 | 可删 |
| `inbox/.partial/` | 未收齐的文件分片 | 可删（1 小时后自动清） |

## 7. 日常使用

### 7.1 手机能做什么

| 功能 | 入口 | 实测延迟 |
| --- | --- | --- |
| 看电脑是否在线 | 状态页顶部灯 | 15~45 秒 |
| 看任务执行到哪、有没有卡住 | 状态页「任务监测」 | 15~45 秒 |
| 下发指令（启动/停止/查状态/看任务/下载文件/帮助） | 指令页按钮 | 15~60 秒 |
| 发自然语言 | 指令页输入框 | **需要模型**（见 7.3） |
| 手机 → 电脑传文件 | 传输页 | 15~60 秒 + 分片耗时 |
| 电脑 → 手机收文件 | 传输页收件箱 | 同上 |

### 7.2 「卡住」是怎么判断的

任务监测里每个运行中的任务会显示「已跑 xx · 日志静止 xx」。如果**日志超过 3 分钟没动静**，标记为 **「⏸ 疑似卡住」**。这是启发式判断（看日志文件 mtime），不是绝对准确——有些任务确实长时间无输出。

### 7.3 关于「省积分」

| 操作 | 是否调用模型 | 说明 |
| --- | --- | --- |
| 遥测上报 | ❌ | 本地代码写邮箱 |
| 结构化指令（start/stop/status/tasks/download/help） | ❌ | 本地正则解析后直接执行 |
| 文件传输 | ❌ | 本地分片 + base64 |
| 自由文本指令 | ✅ | 存进 `queue/needs-model.json`，等 WorkBuddy 云端任务解析 |

自由文本指令在电脑端只会得到「已排队等待云端解析」的回执，**不会自动执行**——这是设计如此（省积分铁律）。

## 8. 故障排查

### 8.1 电脑端

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 设置里没有鸿驿卡片 | 插件未组合进 profile | 检查 `dsh.profile.bundles` 是否含 `dsh-hongyi`；重启桌面版 |
| `/hongyi/state` 返回 404 | 同上，或 Host 半边 import 失败 | 看 DSH 启动日志里 `N entries did not activate` 有没有 hongyi |
| `/hongyi/*` 返回 401 | 访问了别的服务端口 | 端口认错，确认是本进程监听的 GUI 端口 |
| 自检「信箱可达」失败 | 授权码错 / 网络问题 | 重新生成授权码；`Test-NetConnection imap.qq.com -Port 993` |
| 日志里 `signature mismatch` | 两端设备密钥不一致 | 重新复制设备密钥，两端都改 |
| `AUTHENTICATE failed` | 用了登录密码而非授权码 | 见第 2 节 |

### 8.2 手机端

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 一直显示「未连接」 | 凭据填错 | 检查邮箱地址/授权码/设备密钥三项 |
| 状态页一直「电脑离线」 | 电脑关机或 DSH 没开 | 开电脑、开 DSH |
| 指令一直「等待回执…」 | ① 设备密钥不一致 ② 电脑没开 ③ 邮箱延迟 | 看电脑端 `journal.ndjson` 有没有 `command-executed` |
| 收不到电脑发的文件 | App 没在前台轮询 | 打开传输页点刷新 |
| 传文件失败 | 超过 200MB / 网络断 | 分片重试，或换小文件 |

### 8.3 关键日志位置

| 日志 | 路径 |
| --- | --- |
| 鸿驿操作日志 | `%DSH_HOME%\hongyi\journal.ndjson` |
| DSH 崩溃日志 | `%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*.log` |
| 后台任务日志 | `<工作目录>\.dsh\bgjobs\<id>\stdout.log` |

## 9. 安全说明

- 授权码与设备密钥存在 `credentials.json`，**不进 DSH 的 profile 配置**，不会同步到任何地方。
- 消息走邮件，意味着**经过腾讯的邮件服务器**。内容是明文 JSON（只有签名保证不被篡改，**没有加密**）。**不要用它传敏感文件。**
- 设备密钥泄露等于别人能给你的电脑下指令。**重新生成后两端都要改**。
- 鸿驿只写 `%DSH_HOME%\hongyi\` 和收件目录，不碰你的其他文件。
- 插件不上报任何遥测到邮箱以外的地址。

## 10. 卸载

1. 手机卸载 APK。
2. 电脑端移除插件：
   ```powershell
   & "...\dsh.cmd" plugin --profile desktop remove dsh-hongyi
   ```
3. 删除数据目录 `%DSH_HOME%\hongyi\`（**注意**：里面有你生成的设备密钥和授权码）。
4. 可选：去 QQ 邮箱撤销那个授权码（重新生成一个即可让旧的失效）。
